RESUMEN DE CAMBIOS PARA REGISTRO DE USUARIOS CON RTK QUERY

1. ARCHIVO: store/index.js
- Se creo el store global de Redux.
- Se registro el reducer de usuariosApi.
- Se agrego el middleware de RTK Query.
- Este archivo permite que toda la app use cache, queries y mutations.

2. ARCHIVO: store/api/usuariosApi.js
- Se creo la API de RTK Query para usuarios.
- Se configuro baseUrl apuntando al API Gateway.
- Se agrego prepareHeaders para enviar el token JWT de Firebase automaticamente.
- Se definieron endpoints:
  - obtenerUsuarios: trae usuarios por rol.
  - crearUsuario: crea usuario en backend si se quiere usar por mutation directa.
  - eliminarUsuario: elimina usuario por id.
- Se configuraron tags para refrescar la tabla automaticamente.

3. ARCHIVO: hooks/admin/useUsuarios.js
- Se reemplazo el hook mock que usaba useState local.
- Ahora el hook consume RTK Query.
- Usa useObtenerUsuariosQuery para traer usuarios reales.
- Usa useEliminarUsuarioMutation para borrar usuarios.
- Usa register del AuthContext para crear usuarios.
- Se genero una contraseña temporal automaticamente.
- Se convirtio el rol en idRol para enviarlo al backend.

4. ARCHIVO: auth/AuthContext.jsx
- No hubo que rehacerlo completo porque ya estaba bien.
- Se reutilizo register().
- register() hace dos pasos:
  1) crea el usuario en Firebase Auth.
  2) llama syncUserWithBackend() para crear el perfil en PostgreSQL por medio del gateway.
- Esto significa que el boton de crear usuario ya aprovecha la logica existente.

5. ARCHIVO: gateway/gatewayService.js
- Se reutilizo la funcion syncUserWithBackend().
- Esta funcion manda uid, nombre, apellido e idRol al backend.
- Tambien quedan listos los helpers apiGet, apiPost, apiPut y apiDelete para otras secciones futuras.
- Ojo: debes confirmar que la ruta correcta del backend sea /api/usuarios/usuarios si ves doble usuarios.

6. ARCHIVO: main.jsx
- Se agrego Provider de react-redux.
- Se envolvio la app con <Provider store={store}>.
- Esto es obligatorio para que RTK Query funcione en toda la aplicacion.

7. ARCHIVO: pages/admin/GestionUsuarios.jsx
- Ya no usa usuarios mock locales.
- Ahora usa el hook useUsuarios(tipoUsuario).
- El boton crear usuario llama crearUsuario().
- Si sale bien, se muestra la contraseña temporal en el modal.
- La tabla deberia actualizarse sola gracias a RTK Query.

8. VALIDACIONES
- Hay que revisar que no se use validarContacto para crear usuarios.
- Lo correcto es una validacion de usuario, por ejemplo validarUsuario.
- Campos esperados para crear usuario:
  - nombre
  - apellido
  - email
  - rol

PASOS PARA PROBAR SI FUNCIONA

PASO 1: revisar dependencias
- Verifica que tengas instalados:
  - @reduxjs/toolkit
  - react-redux
- Si no estan, instala con:
  npm install @reduxjs/toolkit react-redux

PASO 2: revisar main.jsx
- Confirma que App este envuelta por Provider y AuthProvider.
- Si Provider no esta, RTK Query no va a funcionar.

PASO 3: iniciar sesion
- Debes entrar con un usuario autenticado.
- Si no hay sesion, el gateway no podra adjuntar el token de Firebase.

PASO 4: entrar a gestion de alumnos
- Ve a la ruta de admin/alumnos.
- Abre la pestaña Network del navegador.
- Revisa si se dispara un GET al endpoint de usuarios.
- Si carga la tabla, la query funciona.

PASO 5: probar crear alumno
- Haz click en nuevo alumno.
- Completa nombre, apellido y email.
- Envialo.
- Revisa tres cosas:
  1) se crea en Firebase Auth.
  2) se crea en PostgreSQL por el backend.
  3) aparece la contraseña temporal en el modal.

PASO 6: revisar la tabla
- Cierra el modal.
- El usuario nuevo deberia aparecer sin recargar la pagina.
- Si aparece, la invalidacion de cache funciono.

PASO 7: probar eliminar
- Haz click en borrar.
- Revisa si se ejecuta DELETE en Network.
- Verifica que desaparezca de la tabla.

PASO 8: revisar errores comunes
- Error 401 o 403:
  - el token no esta llegando bien o no hay sesion.
- Error 404:
  - la ruta del endpoint no coincide con el backend.
- Error CORS:
  - el backend no permite peticiones desde el frontend.
- Error de validacion:
  - revisa si estas usando validarContacto en vez de validarUsuario.

CHECKLIST FINAL
- store configurado
- Provider agregado en main.jsx
- usuariosApi creado
- useUsuarios actualizado
- register reutilizado desde AuthContext
- rutas correctas del gateway
- sesion iniciada antes de probar
- validacion correcta del formulario

Si algo falla, revisa primero Network y la consola del navegador, porque ahi vas a ver si el problema esta en Firebase, en el gateway o en la ruta del backend.
